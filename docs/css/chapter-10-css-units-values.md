🧠 الفكرة المبسطة

تخيلي بتاخدي مقاسات لهدوم - ممكن تاخدي "مقاس ثابت بالسم" (زي px)، أو "مقاس نسبي لمقاس تاني" (زي em/rem)، أو "نسبة من مساحة الغرفة" (زي %). كل طريقة قياس بتجاوب على سؤال مختلف.

🔧 الصياغة التقنية

الوحدات بتنقسم لنوعين: Absolute (ثابتة زي px) وRelative (بتتغير حسب سياق معين).

🎯 الربط

"السؤال اللي بيفرّق بين Mid وSenior مش 'إيه الوحدة الأفضل' - هو 'إيه العلاقة اللي القيمة دي المفروض تكون مرتبطة بيها؟' (viewport؟ container؟ root font-size؟ سياق العنصر نفسه؟)."

🎨 في Figma

الأدوات زي Figma أصلًا بتشتغل بمقاس ثابت (px) لكل الـ frames والعناصر بشكل افتراضي - وده فرق جوهري عن الويب اللي فيها وحدات نسبية وفلوييد بطبيعتها. ده سبب رئيسي إن أي تصميم Figma محتاج "ترجمة" واعية لما يتحول لكود، مش نسخ الأرقام حرفيًا.

10.2 px
🔧 الصياغة التقنية
css
.card {
  width: 300px;
  padding: 24px;
  border-radius: 8px;
}

مناسبة لـ: border, border-radius, أحجام أيقونات، قيم دقيقة في UI components.

🎯 الربط

"px مش 'وحدة سيئة' - هي مناسبة تمامًا للقيم اللي المفروض تفضل ثابتة بصريًا زي سمك حدود. المشكلة بس لما تُستخدم في كل حاجة بما فيها الـ typography، وده بيقلل من استجابة التصميم لإعدادات إمكانية الوصول في المتصفح."

🎨 في Figma

px هي وحدة القياس الافتراضية والوحيدة تقريبًا اللي بتشتغلي بيها في Figma للـ frames والعناصر - يعني أي قيمة px بتحطيها في Figma بتتنقل مباشرة لـ CSS من غير أي تحويل.

10.3 %
🔧 الصياغة التقنية
css
.container {
  width: 80%; /* نسبة من عرض الـ parent */
}

img {
  max-width: 100%;

}
🎯 الربط

"القيمة بتتحسب دايمًا نسبة لبُعد الأب المباشر، مش الصفحة كلها - ده مهم تفتكريه لو حسبتي رقم غلط."

🎨 في Figma

⚠️ محتاجة تأكيد: أقرب مفهوم في Figma هو خاصية "Fill container" جوه الـ Auto Layout - العنصر بيتمدد لياخد نسبة من المساحة المتاحة جوه أبوه، بمنطق قريب من %، لكن مش نفس الآلية بالظبط. يفضل تتأكدي من التفاصيل الدقيقة من داخل Figma نفسها لو التطابق مهم لشغلك.

10.4 em
🧠 الفكرة المبسطة

تخيلي مقاس نسبي لجسم شخص معين - "نص طول الشخص ده". لو الشخص طوله اتغيّر، المقاس النسبي بيتغيّر معاه تلقائيًا.

🔧 الصياغة التقنية
css
.parent {
  font-size: 20px;
}
.child {
  font-size: 1.5em; /* 1.5 × 20px = 30px */
}
🎯 الربط

"em بتتأثر بالـ font-size المرجعي - وده ممكن يبقى font-size العنصر نفسه، أو أبوه، حسب الخاصية اللي بتستخدميها فيها. الـ nesting العميق مع em ممكن يدّي قيم مش متوقعة لو الاستخدام مش مقصود."

🆕 فخ Senior: line-height مع em والـ Compounding Effect
css
.parent {
  font-size: 16px;
  line-height: 1.5em; /* بتتحسب فورًا لـ 24px، والقيمة المحسوبة دي هي اللي بتتوارث */
}
.child {
  font-size: 24px;
  /* هيورث line-height: 24px (كقيمة ثابتة)، مش نسبة 1.5 من حجمه الجديد */
}

الحل: استخدام قيمة بدون وحدة:

css
.parent {
  line-height: 1.5; /* الرقم نفسه هو اللي بيتوارث، مش القيمة المحسوبة */
}
.child {
  font-size: 24px;
  /* هيحسب: 1.5 × 24px = 36px تلقائيًا - صح */
}

"ده أشهر فخ عملي مرتبط بـ em في مقابلات Senior - الفرق بين وراثة 'قيمة محسوبة' ووراثة 'نسبة'."

🎨 في Figma

مفيش مفهوم مباشر لـ em في Figma - كل نص بتحددي حجمه بالـ px مباشرة. أقرب حاجة هي Text Styles (نمط نص محفوظ تقدري تطبقيه على عناصر متعددة)، وهي أقرب لمفهوم Design Tokens عمومًا مش لـ em تحديدًا.

10.5 rem
🧠 الفكرة المبسطة

بدل ما تاخدي مقاس نسبي لكل شخص لوحده، تاخدي مقياس موحد ثابت (زي "المتر") وتقيسي بيه الكل - كل حاجة بترجع لنفس المرجع الواحد.

🔧 الصياغة التقنية
css
html {
  font-size: 16px;
}
.title {
  font-size: 2rem; /* 2 × 16px = 32px، دايمًا بالنسبة لـ html بس */
}
🎯 الربط

"الفرق الجوهري عن em: rem بتتجاهل أي تعشيش (nesting) وبترجع لمرجع واحد ثابت - الـ html. ده اللي بيخليها الخيار الأنسب لـ Design Systems، لأن القيم بتفضل متسقة بغض النظر عن مكان العنصر في الشجرة."

🎨 في Figma

⚠️ محتاجة تأكيد: مفيش وحدة rem حرفية في Figma، لكن استخدام Variables (لو بتستخدمي خطة تدعمها) بيسمحلك تعرّفي "قيمة أساسية" مركزية وتربطي بيها باقي القيم - ده أقرب مفهوميًا لفكرة "مرجع واحد موحد" اللي rem بتقوم عليها، لكن الآلية التقنية مختلفة تمامًا عن CSS. يفضل تتأكدي من تفاصيل الـ Variables الحالية في حسابك.

10.6 em vs rem
	em	rem
المرجع	العنصر نفسه/أبوه	الـ html الجذر فقط
بيتأثر بالـ nesting	✅ (compounding)	❌
الأنسب لـ	مكوّنات مرتبطة بحجمها الذاتي (زرار مثلاً)	Design systems، typography عامة
🎯 الربط

"لو عايزة القيمة تكبر مع حجم الخط بتاع نفس المكوّن (زرار بحجم خط أكبر يبقى عنده padding أكبر تلقائي) → em. لو عايزة قيمة موحدة بغض النظر عن أي حاجة تانية حواليها → rem."

10.7 vw / vh
🔧 الصياغة التقنية
css
.hero {
  width: 80vw;       /* 80% من عرض الـ viewport */
  min-height: 100vh; /* 100% من ارتفاع الـ viewport */
}
⚠️ تذكير من فصل 9

100vh بتسبب مشاكل على الموبايل بسبب شريط العنوان المتغيّر - البديل الحديث dvh/svh/lvh (اتشرحوا بالتفصيل في الفصل السابق).

🎨 في Figma

⚠️ محتاجة تأكيد: Figma بتشتغل بـ frames بمقاسات px ثابتة لكل breakpoint (موبايل/تابلت/ديسكتوب كفريمات منفصلة)، مش بمفهوم "viewport ديناميكي" زي المتصفح. يعني معظم المصممين بيحاكوا الـ vw/vh يدويًا برسم فريمات متعددة بمقاسات مختلفة، مش بخاصية مباشرة اسمها viewport unit.

10.8 vmin / vmax
🔧 الصياغة التقنية
css
.circle {
  width: 50vmin;  /* نسبة من أصغر بُعد (العرض أو الارتفاع) */
  height: 50vmin;
}
.element {
  width: 50vmax;  /* نسبة من أكبر بُعد */
}
🎯 الربط

"vmin مفيدة لما عايزة عنصر (زي دايرة) يفضل متناسب حتى لو الشاشة اتقلبت لـ landscape/portrait - بتاخدي دايمًا أصغر بُعد كمرجع عشان العنصر ميخرجش برة الشاشة."

10.9 ch
🔧 الصياغة التقنية
css
.article {
  max-width: 65ch; /* عرض متناسب مع حرف الصفر في الخط المستخدم */
}
🎯 الربط

"الفايدة الحقيقية مش رقم دقيق حرفيًا، لكنها طريقة مرتبطة بالخط نفسه لتحديد عرض سطر مريح للقراءة - مفيدة جدًا في المقالات والـ documentation."

🎨 في Figma

مفيش وحدة ch في Figma - المصممين بيحددوا عرض صندوق النص يدويًا (بالـ px) وبيقيسوا بالعين تقريبًا كام حرف بيدخل في السطر، بدل ما يبقى فيه حساب تلقائي مرتبط بالخط.

10.10 fr
🔧 الصياغة التقنية
css
.grid {
  display: grid;
  grid-template-columns: 1fr 2fr; /* تقسيم بنسبة 1:2 */

🎯 الربط

"مهم: fr مش وحدة عامة تستخدميها في أي property - استخدامها الأساسي والوحيد عمليًا هو جوه CSS Grid."

🎨 في Figma

⚠️ محتاجة تأكيد: أقرب مفهوم هو خاصية توزيع المساحة جوه Auto Layout لما بتخلي عنصر معين "Fill container" بدل حجم ثابت - المنطق قريب من فكرة "ياخد نصيبه من المساحة المتاحة" لكن التفاصيل التقنية الدقيقة تستاهل تتأكدي منها بنفسك.

10.11 calc()
🔧 الصياغة التقنية
css
.sidebar {
  width: calc(100% - 300px);
}
⚠️ تحذير تقني حرج

لازم مسافة قبل وبعد + و- جوه calc()، وإلا الـ declaration كلها بتتجاهل من المتصفح بصمت:

css
/* غلط - هتتجاهل تمامًا، من غير أي رسالة خطأ */
width: calc(100%-300px);

/* صح */
width: calc(100% - 300px);

بعكس ذلك، * و/ مش شرط تكون ليهم مسافة.

🎯 الربط

"ده مش مجرد أسلوب كتابة - المسافة هنا جزء من الـ syntax الرسمي. من غيرها، الكود بيفشل بصمت من غير أي error واضح في الـ console، وده بيخلي تشخيص المشكلة صعب."

🎨 في Figma

مفيش دوال حسابية (calc) داخل خصائص Figma مباشرة - أي حسبة بتتم يدويًا بره الأداة قبل ما تدخلي الرقم النهائي.

10.12 min() / max()
🔧 الصياغة التقنية
css
.container {
  width: min(90%, 1200px); /* الأصغر من الاتنين */
}
.container {
  padding-inline: max(20px, 5vw); /* الأكبر من الاتنين */
}
🎯 الربط

"min() بتضمنلك سقف أقصى (متتجاوزيش 1200px حتى لو 90% أكبر منها)، وmax() بتضمنلك حد أدنى (الـ padding مايقلش عن 20px حتى لو 5vw أصغر)."

10.13 clamp()
🔧 الصياغة التقنية
css
h1 {
  font-size: clamp(2rem, 5vw, 4rem);
  /*              min   ideal  max */
}
⚠️ نقطة دقيقة يستاهل الانتباه ليها

القيم لازم تكون بالترتيب المنطقي (min ≤ preferred ≤ max). لو الـ preferred value حسابها طلع أصغر من الـ min أو أكبر من الـ max، المتصفح هيرجع للحد المناسب تلقائيًا (يعني الدالة مش هتنكسر)، لكن النتيجة البصرية ممكن متبقاش زي المتوقع لو الأرقام مش متسقة منطقيًا من الأساس.

🎯 الربط

"clamp() هي عمليًا min() وmax() مع بعض في دالة واحدة - بتديكي قيمة fluid لكن بحدود آمنة من الطرفين."

🎨 في Figma

مفيش مكافئ مباشر - المصمم بيحدد قيمة ثابتة مختلفة لكل breakpoint (فريم منفصل)، بدل قيمة واحدة "سائلة" بتتغير تلقائيًا زي clamp() في المتصفح.

10.14 مثال حقيقي يجمع أكتر من Unit
css
.container {
  width: min(90%, 1200px);
  margin-inline: auto;
}
.grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
  gap: 1.5rem;
}
.title {
  font-size: clamp(2rem, 5vw, 4rem);
}
.article {
  max-width: 65ch;
}
🎯 الربط

"لاحظي إن كل وحدة استخدمناها لسبب مختلف: %/min() للعرض الـ responsive، rem للمسافات، fr للـ Grid، clamp() للـ typography الـ fluid، وch لعرض النص المقروء. اختيار الوحدة بقى قرار هندسي، مش حفظ syntax."

🎯 أشهر أسئلة Senior
1. em vs rem؟

em نسبية لسياق العنصر (نفسه أو أبوه)، rem نسبية للـ root font-size بس.

2. ليه ميفضلش نستخدم em مع line-height؟

بسبب الـ Compounding Effect - القيمة المحسوبة (px) بتتوارث بدل النسبة نفسها. الحل: قيمة بدون وحدة زي line-height: 1.5.

3. calc(100%-300px) هتشتغل؟

لأ. لازم مسافة حوالين +/- جوه calc()، وإلا الـ declaration بتتجاهل بالكامل.

4. الفرق بين min() وmax() وclamp()؟

min() بتاخد الأصغر، max() بتاخد الأكبر، clamp() بتجمع الاتنين مع قيمة مفضّلة fluid في النص.

5. ليه نستخدم ch؟

للتحكم في عرض سطر النص بطريقة مرتبطة بالخط نفسه، مفيدة للمقالات والمحتوى الطويل.

🧠 كيف تختاري الـ Unit؟
قيمة ثابتة تمامًا؟              → px
مرتبطة بالـ parent/container؟   → %
مرتبطة بـ root typography scale؟ → rem
مرتبطة بسياق/حجم خط العنصر؟      → em (واحذري line-height!)
مرتبطة بالـ viewport؟            → vw/vh/vmin/vmax (أو dvh على الموبايل)
توزيع مساحة جوه Grid؟            → fr
عرض نص مقروء؟                    → ch
محتاجة حسابات؟                   → calc() (لا تنسي المسافات!)
محتاجة حد أقصى/أدنى؟             → min()/max()/clamp()
⭐ أهم نقطة في الفصل

السؤال مش "إيه أفضل وحدة؟" - السؤال "إيه العلاقة اللي القيمة دي المفروض تتبعها؟"

🎤 جملتك النموذجية في المقابلة

"Unit choice reflects the relationship a value should have — rem for a consistent root-based scale, em for values that should scale with a component's own font size, and viewport or grid-relative units when the relationship is to available space rather than typography. A classic pitfall is using em for line-height, which bakes in a computed pixel value that children inherit rigidly — using a unitless value avoids that compounding issue. I also make sure to include spaces around +/- inside calc(), since omitting them silently invalidates the whole declaration."
