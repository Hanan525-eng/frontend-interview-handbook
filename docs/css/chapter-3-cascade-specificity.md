## السؤال الاول

## **What is the Cascade?**

### 🧠 الفكرة المبسطة

تخيلي إنك بتحكمي في نزاع بين كام شخص بيدوا رأيهم في نفس القرار. عشان تاخدي قرار عادل، بتسأليهم 3 أسئلة بالترتيب:

```
1. مين ده أصلاً؟ (مديرك، زميلك، ولا حد غريب؟)
2. لو نفس المستوى... مين كلامه أدق؟
3. لو لسه متساويين... مين اتكلم آخر واحد؟
```

بتوقفي عند أول سؤال بيدّيكي إجابة واضحة، ومش بتكمّلي للي بعده إلا لو لسه فيه تعادل.

### 🔧 الصياغة التقنية

الـ **Cascade** هو الخوارزمية اللي بيتبعها المتصفح لحل التعارض بين قواعد CSS متعددة، بنفس الترتيب الهرمي:

```
1. Origin & Importance   (مين كتب القاعدة؟ وهل فيها !important؟)
        ↓ (لو متساويين)
2. Specificity           (وزن الـ Selector نفسه)
        ↓ (لو متساويين برضه)
3. Source Order          (مين مكتوب آخر واحد في الملف)
```

### 🎯 الربط

*"الـ Cascade مش خطوة واحدة - هو نظام قرار هرمي بيوقف عند أول مستوى بيدي إجابة حاسمة. لو الـ Origin وحده كفى (مثلاً واحد استخدم `!important` والتاني لأ)، المتصفح مش هيروح يحسب الـ Specificity أصلاً."*

---

### 3.2 Origin & Importance

### 🧠 الفكرة المبسطة

فكري في **3 أشخاص** بيدّوا رأي عن لون الزرار، وكل واحد صوته أعلى من اللي قبله بشكل افتراضي:

```
1. المتصفح (صوت خافت جدًا)  → "رأيي إن الزرار رمادي (الافتراضي)"
2. المطور - انتِ (صوت متوسط) → "لأ، أنا عايزاه أزرق"
3. المستخدم (صوت خافت، نادر يتكلم) → عادةً ساكت
```

في الوضع الطبيعي، **صوتك انتِ (المطور) هو الأعلى**، فرأيك بيكسب.

لكن `!important` زي **مايك** - لو حد أخده وتكلم بيه، صوته بقى أعلى فجأة. المشكلة إن لو **المستخدم** (النادر ده) استخدم المايك بتاعه، صوته هيبقى أعلى من صوتك انتِ حتى لو انتِ ماسكة مايك برضه.

### 🔧 الصياغة التقنية

ترتيب المصادر من الأضعف للأقوى:

css

```css
1. User Agent styles        /* الستايل الافتراضي اللي المتصفح حاطه */
2. User styles               /* إعدادات إضافية نادرة من المستخدم */
3. Author styles              /* كودك انتِ */
4. Author !important          /* أي حاجة في كودك عليها !important */
5. User !important            /* لو المستخدم استخدم !important */
6. User Agent !important      /* نادر جدًا */
```

### 🎯 الربط

*"الـ `!important` مش مجرد أداة `bypass` عامة - هي بترفع القاعدة لمستوى Origin أعلى، وده بيعكس ترتيب الأولوية الطبيعي بين Author وUser. عمليًا، النقطة دي بتظهر كـ gotcha question: لو الاتنين حطوا `!important`، مين هيكسب؟ الإجابة: مش أنتِ، لأن الـ User `!important` بيغلب الـ Author `!important`."*

---

### 3.3 Specificity

### 🧠 الفكرة المبسطة

فكريها زي **دقة العنوان البريدي**. كل ما العنوان بقى أخص، كل ما اتصدّق أكتر:

```
"روحي مصر"                    → عام جدًا
"روحي القاهرة"                 → أدق شوية
"روحي شارع كذا في القاهرة"      → أدق أكتر
"روحي البيت رقم 5 بالظبط"       → الأدق، محدد لحتة واحدة بس
```

**النقطة المهمة**: لو جمّعتي 100 عنوان عام ("روحي مصر" × 100)، برضه مش هيبقوا أدق من عنوان واحد محدد ("البيت رقم 5"). العدد مش بيعوّض الدقة.

### 🔧 الصياغة التقنية

الخصوصية بتتحسب في **4 خانات مستقلة تمامًا عن بعض**: `(Inline, ID, Class, Type)`

css

```css
* { }              /* (0,0,0,0) - "روحي مصر" */
div { }             /* (0,0,0,1) - "روحي القاهرة" */
.card { }            /* (0,0,1,0) - "روحي الشارع" */
#header { }          /* (0,1,0,0) - "البيت رقم 5" */
```

مثال متدرج:

css

```css
p { color: black; }              /* (0,0,0,1) */
p.description { color: blue; }    /* (0,0,1,1) */
#main-text { color: green; }      /* (0,1,0,0) - الفائز */
```

### 🎯 الربط

*"الخانات مستقلة عن بعض زي ما 'روحي مصر' مهما اتكررت مش هتبقى أدق من عنوان بيت محدد. ده أساس فخ المقابلة الأشهر:"*

#### 🪤 فخ المقابلة الشهير

**السؤال**: "لو طبّقنا 100 كلاس `.c1.c2...c100 { color: red; }`، وجه بعده `#myId { color: blue; }` - مين هيفوز؟"

**الإجابة**: الـ **ID دايمًا** (`blue`). مهما كتّرتي العناوين العامة، مش هتوصلي لدقة عنوان محدد واحد. الخانة الأعلى بتكسب بغض النظر عن أي رقم في الخانة الأقل منها.

### 3.4 Inheritance (الوراثة)

### 🧠 الفكرة المبسطة

فكريها زي **الصفات الوراثية في العيلة**:

- **بتتورث طبيعي**: لون العين، شكل الوش - الابن بياخدها من غير ما حد "يوريه"
- **مش بتتورث**: ملابس أبوه، ساعته - كل واحد بتاعته، محدش وارثها تلقائي

لو عايزة "تجبري" الابن ياخد حاجة مش بتتورث عادةً، لازم تقوليله صراحة: **"البس زي أبوك"**.

### 🔧 الصياغة التقنية

css

```css
.parent {
  color: red;              /* بتتورث تلقائي (نص/طباعة) */
  font-family: 'Cairo';     /* بتتورث تلقائي */
  border: 1px solid black;   /* مش بتتورث (box model) */
  margin: 20px;               /* مش بتتورث */
}

.child {
  border: inherit;   /* إجبار الوراثة يدويًا */
}
```

### 🎯 الربط

*"القاعدة العامة: خصائص النص والطباعة (`color`, `font-family`, `line-height`) بتتورث تلقائي، وخصائص الـ layout (`margin`, `padding`, `border`) لأ - عشان لو الـ border كانت بتتورث، أي عنصر متداخل هياخد نفس الحدود ويكسر أي layout معقد."*

---

### 3.5 الأربع قيم: inherit / initial / unset / revert

### 🧠 الفكرة المبسطة

انسي الجدول، وفكري في سؤال واحد بس: **"لو مسحت الـ style بتاعي، الزرار هيرجع لإيه؟"**

- `inherit` = **"هرجع زي أبويا بالظبط"** (حتى لو مش من نوع اللي بيتورث عادةً)
- `initial` = **"هرجع زي ما القانون (CSS spec) بيقول"**
- `unset` = **"سيبيها تتصرف طبيعي"** - لو بتتورث هتورث، لو لأ هترجع initial
- `revert` = **"هرجع زي ما كانت قبل ما أتدخل أصلاً"** - يعني ستايل المتصفح الافتراضي

### 🔧 الصياغة التقنية

css

```css
/* افترضي إن المتصفح بيدي h1 حجم افتراضي 2em */
h1 { font-size: 3rem; }              /* الـ author style بتاعنا */

h1.reset-unset  { font-size: unset; }   /* هتاخد initial (font-size مش بتتورث) */
h1.reset-revert { font-size: revert; }  /* هترجع لـ 2em تقريبًا (ستايل المتصفح) */
```

### 🎯 الربط

*"الفرق الجوهري بين `unset` و`revert`: `unset` بتنسى وجودك انتِ كمطورة وترجع لقاعدة عامة (initial أو inherit حسب نوع الخاصية)، بينما `revert` بترجع بالظبط لأول حاجة كانت موجودة قبل ما تتدخلي أصلاً - ستايل المتصفح."*

---

### 3.6 Source Order

### 🧠 الفكرة المبسطة

لو اتنين زمايلك بنفس الدرجة الوظيفية بالظبط (يعني نفس دقة العنوان) قالوا رأيين مختلفين، هتسمعي لمين؟ اللي **اتكلم آخر واحد**. بس، مفيش تعقيد تاني.

### 🔧 الصياغة التقنية

css

```css
.button { color: blue; }
.button { color: red; }  /* الفائز - نفس الـ specificity، لكن اتكلمت آخر */
```

### 🎯 الربط

*"ده آخر معيار في السلسلة، وبيتفعّل بس لو الأصل (Origin) والخصوصية (Specificity) متساويين تمامًا. لو حد فاكر إن السطر الأخير دايمًا بيكسب، ده غلط - لازم الأول Origin وSpecificity يبقوا متعادلين."*

## 🎯 Interview Question

#### إيه الفرق بين `unset` و`revert`؟

- `unset`: بتنضم للسلوك الطبيعي للخاصية - لو موروثة تتصرف زي `inherit`، لو لأ زي `initial`
- `revert`: بترجع لستايل المتصفح الافتراضي، بغض النظر عن أي حاجة تانية

**مثال للتفرقة**: على `display` (مش موروثة)، `unset` هترجعها لـ `initial` (غالبًا `inline`)، بينما `revert` هترجعها للقيمة الافتراضية اللي المتصفح حاططها لنوع العنصر ده تحديدًا (زي `block` للـ `div`).

## 🎯 Senior Note

الـ Cascade **مش نظام واحد** - هو **3 أنظمة متتالية**، وكل واحد بيتفعّل بس لو اللي قبله متعادل:

```
Cascade
   │
   ├── 1. Origin & Importance  ← بيحسم لو مختلفين
   ├── 2. Specificity          ← بيتفعّل لو الأول متساوي
   └── 3. Source Order         ← بيتفعّل لو الأول والتاني متساويين
```

المطور اللي بيعرف بس الـ Specificity وبيتجاهل الـ Origin، هيتفاجئ لما `!important` من كود تاني تغلب الـ ID بتاعته، أو لما قاعدتين بنفس الوزن تكسب واحدة منهم بس لمكانها في الملف.

> **"The Cascade resolves conflicting rules through three sequential layers — origin/importance, specificity, then source order — each activating only if the previous one ties. Specificity is calculated in independent categorical columns, so a higher category always wins regardless of how many lower-category selectors are combined. I use `!important` sparingly since overusing it is usually a symptom of deeper specificity problems."**
