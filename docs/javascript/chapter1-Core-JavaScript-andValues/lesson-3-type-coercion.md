# 🟢 Chapter 1 — Lesson 3: Type Coercion

---

## 1. Why it exists

بما إن الجافاسكريبت لغة `Dynamic Typed` (زي ما شرحنا في الدرس اللي فات)، فالسؤال الطبيعي اللي بيظهر:

لو كل متغير ممكن يشاور على قيمة من أي نوع، إيه اللي بيحصل لما نحاول نعمل عملية بين قيمتين من نوعين مختلفين؟

مثال:

```js
const age = "25";
console.log(age + 5);
```

الناتج `30` ولا `"255"`؟

لو الجافاسكريبت لغة صارمة (زي بعض اللغات التانية)، كانت هترمي خطأ فوراً وتوقف البرنامج. لكن مصممي اللغة اختاروا اتجاه مختلف: خلّوا اللغة **تحاول تحوّل النوع تلقائياً** بدل ما توقف، عشان تفضل مرنة وسهلة في الاستخدام. هذا الميكانيزم اسمه **`Type Coercion`**.

---

## 2. Concept

**`Type Coercion`** تعني تحويل قيمة من نوع لنوع تاني عشان عملية معينة تقدر تتنفذ.

```js
"5" + 2
```

هنا الجافاسكريبت بتحوّل الـ `2` لنص، وبتدمج القيمتين:

```
"5" + 2
  ↓
"5" + "2"
  ↓
"52"
```

```js
console.log("5" + 2); // "52"
```

---

## 3. Mental Model 🧠

لما تشوفي عملية بين قيمتين:

```
value1  OP  value2
```

اسألي نفسك بالترتيب:

```
1. القيمتين نوعهم إيه؟
2. العملية (OP) دي إيه؟
3. العملية دي ليها قاعدة خاصة، ولا بتحوّل للأرقام دايماً؟
4. الجافاسكريبت هتحوّل لأنهي نوع؟
5. الناتج هيبقى إيه؟
```

ده أفضل بكتير من حفظ أمثلة منفردة زي `"5" + 2 = "52"`، لأن الهدف إنك تقدري تتوقعي سلوك أي كود جديد تشوفيه، مش تفتكري أمثلة بعينها.

---

## 4. How JavaScript actually behaves

### أ) العمليتان مختلفتان تماماً: `+` مقابل باقي العمليات الحسابية

**معامل `+`:** لو **أي طرف** من الطرفين نصّ (`string`)، العملية بتتحول لدمج نصوص (`String Concatenation`).

```js
"5" + 2   // "52"  (نص + رقم → دمج)
"5" + "2" // "52"
```

**باقي العمليات الحسابية (`-`, `*`, `/`, `%`):** دايماً بتحوّل الطرفين لأرقام، لأنهم مالهمش معنى تاني غير الحساب.

```js
"5" - 2   // 3   (النص اتحول لرقم)
"5" * "2" // 10
"10" - 3  // 7
```

السبب في الاختلاف: `+` بس هي اللي ليها معنى تاني (دمج نصوص) غير الجمع الحسابي، فهي بتدي الأولوية للنص لو موجود. باقي العمليات مالهاش معنى إلا الحساب، فبتفرض التحويل لرقم دايماً.

### ب) التحويل نوعان: تلقائي وصريح

**التحويل التلقائي (`Implicit Coercion`):** الجافاسكريبت بتعمله بنفسها من غير ما تطلبي.

```js
"10" - 2   // الجافاسكريبت حوّلت "10" لرقم من تلقاء نفسها
```

**التحويل الصريح (`Explicit Conversion`):** إنتِ بنفسك بتطلبي التحويل.

```js
Number("10")   // 10
String(10)     // "10"
Boolean(1)     // true
```

### ج) أهم دوال التحويل الصريح

```js
Number("25")     // 25
Number("Hanan")  // NaN
Number("")       // 0
Number(null)     // 0
Number(undefined)// NaN

String(25)        // "25"
String(true)      // "true"
```

### د) التحويل لـ `Boolean`: مفهوم `Truthy` / `Falsy`

أي قيمة في الجافاسكريبت بتتحول لـ `false` جوه شرط (`if`) لو كانت واحدة من الثمانية دول (وهم يُسمّون `Falsy Values`):

```
false
0   و   -0   و   0n
""    (نص فاضي)
null
undefined
NaN
```

**كل قيمة غير كده هي `Truthy`،** حتى لو شكلها فاضي أو غريب. أهم حالتين لازم تنتبهي ليهم:

```js
Boolean([])   // true  ← المصفوفة الفاضية Truthy!
Boolean({})   // true  ← الكائن الفاضي Truthy!
```

## 5. Code Examples (Predict first ✍️)

### مثال أ — العمليات الحسابية

```js
console.log("5" - 2);
console.log("5" + 2);
console.log("5" * "2");
console.log(true + true);
```

<details>
<summary>الإجابة</summary>

```
3
"52"
10
2
```

`true + true`: القيمة `true` بتتحول لرقم `1`، فالعملية بقت `1 + 1 = 2`.
</details>

### مثال ب — تحويل الـ `Object` و`Array`

```js
console.log([] + []);
console.log([] + {});
console.log([1, 2] + [3, 4]);
```

<details>
<summary>الإجابة</summary>

```
""
"[object Object]"
"1,23,4"
```

المصفوفة (`Array`) بتتحول لنص عن طريق `.toString()`. المصفوفة الفاضية `[]` بتبقى `""`. المصفوفة `[1, 2]` بتبقى `"1,2"`. عشان كده `[1, 2] + [3, 4]` هي فعلياً `"1,2" + "3,4"` = `"1,23,4"`.
</details>

### مثال ج — ترتيب العمليات بيغيّر الناتج

```js
console.log(1 + "1" + 1);
console.log(1 + 1 + "1");
```

<details>
<summary>الإجابة</summary>

```
"111"
"21"
```

الجافاسكريبت بتنفذ من الشمال لليمين:

```
1 + "1" + 1
→ "1" + 1    (رقم + نص → دمج، فالرقم بقى نص "1")
→ "11" + 1
→ "11" + "1" → "111"

1 + 1 + "1"
→ 2 + "1"    (رقم + رقم → جمع حسابي عادي)
→ "2" + "1"  (دلوقتي رقم + نص → دمج)
→ "21"
```

نفس الأرقام بالظبط، لكن **ترتيب العمليات** غيّر الناتج بالكامل.
</details>

## 6. Common Mistakes / Misconceptions

**❌ الاعتماد على `if (array)` للتأكد إن المصفوفة مش فاضية**

```js
const items = [];
if (items) {
  console.log("فيه عناصر!"); // ❌ هيتنفذ! لأن [] قيمة Truthy
}

// ✅ الصح:
if (items.length > 0) { }
```

**❌ استخدام `||` مع قيم ممكن تكون صفر**

```js
const discount = 0;
const finalDiscount = discount || 10; // ❌ النتيجة 10 مش 0!
```

`0` قيمة `Falsy`، فـ `||` بتتجاهلها وتاخد القيمة اللي بعدها. الحل: استخدام `??` (`Nullish Coalescing`)، اللي بتفحص `null` و`undefined` بس.

```js
const finalDiscount = discount ?? 10; // ✅ النتيجة 0
```

**❌ افتراض إن `null` و`undefined` بيتحولوا لنفس القيمة الرقمية**

```js
Number(null)      // 0
Number(undefined) // NaN
```

**❌ الاعتقاد إن `Type Coercion` "حاجة سيئة" لازم نتجنبها دايماً**

الأدق: التحويل التلقائي محتاج فهم، والاستخدام الواعي منه مقبول. لكن في كود production لأنظمة كبيرة (زي ERP)، بنفضّل التحويل الصريح لما يكون المقصود مهم، عشان الكود يبقى واضح لأي حد يقراه.

## 7. Real Front-End Example

### التحويل عند استقبال قيمة من input

```jsx
const quantity = event.target.value;
console.log(typeof quantity); // "string" (دايماً، حتى لو type="number")

const total = quantity + 5;
console.log(total); // ⚠️ ممكن تطلع "1005" مش 105
```

الحل هو التحويل الصريح عند نقطة الاستقبال:

```jsx
const quantity = Number(event.target.value);
const total = quantity + 5; // ✅ دايماً جمع حسابي
```

### مثال فلترة في Dashboard

```jsx
// ❌ فيه bug مستترة
const TransactionList = ({ minAmount }) => {
  const effectiveMin = minAmount || 10;
  // لو minAmount = 0 (المستخدم عايز يشوف كل المعاملات من صفر)
  // effectiveMin هتاخد 10 بالغلط، مش 0!
};

// ✅ الحل
const effectiveMin = minAmount ?? 10;
```

## 8. Interview Question 🎯

> **What's the result of `"5" + 5` and `"5" - 5`, and why are they different?**

الإجابة الأدق:

> `+` checks if either operand is a string; if so, it performs string concatenation. The other arithmetic operators (`-`, `*`, `/`, `%`) always convert both operands to numbers, since they have no other meaning. This is why `"5" + 5` returns `"55"` while `"5" - 5` returns `0`.

📌 **تذوّق للدرس الجاي:** فيه سؤال مقابلة أشهر وأعمق من كده: **إيه ناتج `[] == ![]`؟** (والإجابة `true`!). السؤال ده بيحتاج فهم كامل لخوارزمية `Abstract Equality Algorithm`، وهي بالظبط موضوع الدرس الجاي مباشرة (`== vs ===`). هنشرحه هناك بالتفصيل خطوة بخطوة.

## 🧠 Senior Thinking

لو عندك API بترجع:

```json
{ "total": "1500" }
```

وكتبتي:

```js
const finalTotal = response.total + 200; // "1500200" وليس 1700!
```

المشكلة هنا مش إن الجافاسكريبت "غلطت". المشكلة إن عندك **عقد بيانات (`data contract`) غير واضح أو غير متحقق منه**. الحل الصحي في نظام إنتاج (`production`) هو تحويل وفحص البيانات في نقطة واحدة عند دخولها للتطبيق:

```
API Response
     ↓
Validation
     ↓
Normalization / Conversion
     ↓
Application State
     ↓
UI
```

بدل ما كل جزء في الكود يتعامل مع النوع بطريقته الخاصة.

## 🛠 Practice — Build It

اكتبي دالة `safeAdd(a, b)` بتاخد قيمتين ممكن يكونوا جايين من مصدر مش موثوق (زي form أو API)، وترجّع **مجموعهم الحسابي الصحيح دايماً**، بغض النظر عن كونهم نص ولا رقم.

```js
safeAdd(5, 3);       // 8
safeAdd("5", 3);      // 8
safeAdd("5", "3");    // 8
safeAdd("abc", 3);    // ؟ (فكري: إيه المفروض يحصل هنا)
```

تلميح: استخدمي `Number()` صراحة على الطرفين، وفكري إزاي تتعاملي مع حالة `NaN`.

## 💥 Practice — Break It

```js
const discount = 0;
const display = discount || "لا يوجد خصم";
console.log(display);
```

**Predict first ✍️** قبل التشغيل: هيطبع إيه؟ وهل ده السلوك المطلوب فعلاً؟

<details>
<summary>الإجابة</summary>

```
"لا يوجد خصم"
```

القيمة `0` معناها الفعلي "خصم صفر بالمية" (رقم صالح)، لكن `||` بتعاملها كـ `Falsy` وتستبدلها. لو المقصود فعلاً إظهار رسالة بس لو مفيش خصم مُعرَّف خالص (`null`/`undefined`)، الحل `discount ?? "لا يوجد خصم"`.
</details>

## 🔄 Recap

```
Type Coercion = تحويل قيمة من نوع لنوع عشان عملية تتنفذ

+  → لو أي طرف نص → دمج نصوص
-, *, /, %  → دايماً تحويل لأرقام

Implicit  → الجافاسكريبت بتحوّل بنفسها
Explicit  → إنتِ بتطلبي التحويل (Number/String/Boolean)

Falsy values الثمانية: false, 0, -0, 0n, "", null, undefined, NaN
كل حاجة غير كده Truthy (حتى [] و {})

||  → بيتجاهل كل الـ Falsy (خطر مع 0)
??  → بيتجاهل null/undefined بس (أدق للقيم الرقمية)
```

## ✅ Self-Check

**1. Define** — عرّفي `Type Coercion` بكلامك، ووضّحي الفرق بين `Implicit` و`Explicit`.

**2. Predict** — جاوبي على 3 أكواد جديدة فيها عمليات `+` و`-` و`||` أو `??`، واكتبي توقعك قبل التشغيل.

**3. Why** — اكتبي فقرة: "الجافاسكريبت بتعمل `Type Coercion` عشان... والمشكلة اللي ممكن تحصل من التحويل التلقائي هي..."

**4. Apply** — إمتى تفضّلي تعتمدي على `Implicit Coercion`، وإمتى تفضّلي `Explicit Conversion`؟ (مثال عام: قيمة جاية من input مقابل رقمين معروفين جوه الكود).

**5. Debug** — ظهر bug إن مجموع فاتورة بيطلع نص غريب بدل رقم (زي `"1500200"`). إيه أول 3 حاجات هتفحصيها؟

> قاعدة: لو بند واحد من الخمسة ما اتحقّقش، الموضوع لسه ما اتقنش.
